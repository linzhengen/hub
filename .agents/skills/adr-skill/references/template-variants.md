# テンプレートの使い分け

`assets/templates/` に 3 つある。**迷ったら `brief`。**
長さは価値ではない。書かれない ADR より、短い ADR の方がはるかによい。

## brief（既定）

`assets/templates/adr-brief.md` · **30 行以内**

会話で決まった判断を、その場で残すためのもの。
節は 4 つだけ: 何が既定だったか / 何をどう決めたか / 何が変わるか / いつ見直すか。

こんなとき:

- 人が既定・慣行・以前の判断を覆した
- 提示した選択肢から人が選んだ
- エージェントの提案が却下された
- 判断は明確で、比較を書き残すほどの選択肢が無い

**「何が既定だったか」が埋まらないなら、ADR は要らない。**
既定どおりのことをしただけである。

## simple

`assets/templates/adr-simple.md` · 60 行以内

こんなとき:

- 落とした案が 1〜2 個あり、それぞれ 1 文で説明できる
- 実装計画（どのファイル、どの型に倣うか）を書き残す必要がある
- `brief` の「何が変わるか」では収まらない

節: 文脈と課題 → 判断 → 帰結 → 実装計画 → 検証 → 却下した案（任意）→ 補足（任意）

## madr

`assets/templates/adr-madr.md` · 上限なし

こんなとき:

- 本当の選択肢が 3 つ以上あり、構造化した比較を残したい
- 判断の軸（何を基準に選ぶか）を明示する必要がある
- 後で見直される可能性が高く、比較そのものを残しておきたい

節: 文脈と課題 → 判断の軸（任意）→ 検討した選択肢 → 結論 → 非目標 → 帰結
→ 実装計画 → 検証 → 各選択肢の長所と短所（任意）→ 補足（任意）

[MADR 4.0](https://adr.github.io/madr/) に準拠しつつ、実装計画と検証を足している。

## 共通するもの

- **frontmatter**（status / date / decision-makers）
- **見直しの条件** — `brief` は「いつ見直すか」、他は `## 補足` に書く
- **相互リンク** — 関連 ADR / 方向性メモ / PR

`simple` と `madr` はさらに:

- **実装計画** — 影響範囲、依存、倣う型、避けること、移行
- **検証はチェックボックス** — 実際に走るコマンドで書く
- **「どちらでもない点」** — 良い / 悪いの二分に収まらない、受け入れた代償を書く枠

## 選び方

| 目安 | brief | simple | madr |
|:--|:--|:--|:--|
| 落とした案の数 | 0 | 1〜2 | 3 以上 |
| 実装計画が要るか | 不要 | 要る | 要る |
| 戻しやすさ | 戻せる | 戻すのが高くつく | 戻すのが高くつく |

`brief` で書き始めて、収まらなければ広げる。逆は起きない。
