# テンプレートの使い分け

`assets/templates/` に 2 つある。

## simple

`assets/templates/adr-simple.md`

こんなとき:

- 判断が素直（勝者が明らかで、比較が短い）
- 「なぜ・何を・帰結・どう実装するか」があれば足りる
- 落とした案が少なく、1 文ずつで説明できる
- 速さが網羅性より大事

節: 文脈と課題 → 判断 → 帰結 → 実装計画 → 検証 → 却下した案（任意）→ 補足（任意）

## MADR（選択肢が多いとき）

`assets/templates/adr-madr.md`

こんなとき:

- 本当の選択肢が 3 つ以上あり、構造化した比較を残したい
- 判断の軸（何を基準に選ぶか）を明示する必要がある
- 後で見直される可能性が高く、比較そのものを残しておきたい

節: 文脈と課題 → 判断の軸（任意）→ 検討した選択肢 → 結論 → 非目標 → 帰結
→ 実装計画 → 検証 → 各選択肢の長所と短所（任意）→ 補足（任意）

[MADR 4.0](https://adr.github.io/madr/) に準拠しつつ、実装計画と検証を足している。

## 両方に共通するもの

- **frontmatter**（status / date / decision-makers）
- **実装計画** — 影響範囲、依存、倣う型、避けること、移行。
  ADR をエージェント向けの仕様にしているのはこの節である
- **検証はチェックボックス** — 実際に走るコマンドで書く
- **「どちらでもない点」** — 良い / 悪いの二分に収まらない、受け入れた代償を書く枠
- **補足** — 相互リンク、後続、再考の引き金

## 選び方

| 目安 | simple | MADR |
|:--|:--|:--|
| 本当の選択肢の数 | 1〜2 | 3 以上 |
| 影響範囲 | 1 つの層 | 層をまたぐ |
| 戻しやすさ | 戻せる | 戻すのが高くつく |
| 想定寿命 | 数か月 | 年単位 |

迷ったら simple。議論の中で複雑さが出てきたら MADR に広げればよい。
