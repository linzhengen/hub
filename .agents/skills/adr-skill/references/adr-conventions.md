# ADR 規約

## 置き場

`docs/decisions/`。**増やさない。**

`docs/design/`（方向性メモ）と `docs/tasks/`（残タスク）が既にあり、
4 つ目の置き場を作ると「同じことが 2 か所にある」状態になる。
このリポジトリが `apicatalog` や `auth.Earliest` で一貫して避けているのがそれである。

公開サイトには含まれない — `docs/build.mjs` は `docs/site/` と、
生成された OpenAPI / API リファレンスしか読まない。

## ファイル名

`YYYY-MM-DD-english-slug.md`

- 日付は作成日で、frontmatter の `date` と揃える
- スラグは英語・小文字・ハイフン区切り。動詞句にする
  （`scope-a-permission-to-an-organization`、`adopt-architecture-decision-records`）
- 同じ日に複数あってよい。スラグで区別される

**ファイル名は英語、本文は日本語。**`docs/design/`（`iga-direction.md` / 本文は日本語）と
同じ流儀で、コミットメッセージと PR タイトルが英語、PR 本文が日本語なのとも揃う。

## 大きさ

**ADR は短いほど読まれる。**書かれない ADR より、短い ADR の方がはるかによい。

| テンプレート | 目安 |
|:--|:--|
| `brief`（既定） | 30 行以内 |
| `simple` | 60 行以内 |
| `madr` | 上限なし |

`simple` / `madr` は、その長さを判断が実際に要求しているときにだけ使う。

## 必須の節

`brief` は 4 節: 何が既定だったか / 何をどう決めたか / 何が変わるか / いつ見直すか。
**「何が既定だったか」が埋まらないなら ADR は要らない。**

`simple` / `madr` は、さらに:

1. **文脈と課題** — なぜ今か、どんな制約があるか
2. **判断** — 何を選んだか。範囲と非目標を含む
3. **帰結** — 何が楽になり、何が高くつくか、後続作業は何か
4. **実装計画** — 影響範囲、倣う型、避けること、検証

hub 向けに、さらに:

- **却下した案とその理由。**「なぜ素直な方をやらなかったのか」は必ず後から訊かれる
- **検証は実際に走るコマンド。**`make test` / `golangci-lint run ./...` /
  `pnpm test` / `migrate up` など
- **その規則がコードのどこに 1 か所だけ落ちるか。**落ちないなら、判断がまだ抽象的

## status

frontmatter で管理する。

```yaml
---
status: proposed
date: 2026-09-04
decision-makers: linzhengen
---
```

| status | 意味 |
|:--|:--|
| `proposed` | 議論中。まだ決まっていない |
| `accepted` | 生きている判断。従う |
| `rejected` | 検討したが採らなかった |
| `deprecated` | かつて受理されたが、もう当てはまらない。代替の経路を書く |
| `superseded by [題](link)` | 新しい ADR に置き換えられた。**必ず双方向にリンク** |

`rejected` を消さないこと。採らなかった理由こそ、同じ提案が再び来たときに要る。

## frontmatter

| 項目 | 必須 | 内容 |
|:--|:--|:--|
| `status` | ○ | 上記 |
| `date` | ○ | 最後に status が変わった日 |
| `decision-makers` | ○ | 判断を持つ人 |
| `consulted` | — | 意見を求めた相手（双方向） |
| `informed` | — | 結果を伝える相手（一方向） |

## 書き換えについて

- **過去を書き換えない。**学びは `## 補足` に日付付きで追記する
- 判断が置き換わったら、新しい ADR を作って古い方を `superseded` にする
- status の変更と事後の追記は、その場で編集してよい

## 分類

`docs/decisions/` が増えてきたらサブディレクトリで分ける。分け方は
リポジトリの構成に揃えるのが素直である。

```
docs/decisions/
  server/
  ui/
  infra/
```

日付の前置きは分類ごとにローカルでよい。分け方を決めたら索引に書く。
**判断が 20 本を超えるまでは平置きのままでよい** — 早すぎる分類は、
どちらに入れるか迷う ADR を生むだけである。
