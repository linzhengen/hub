# 設計判断の記録 (ADR)

1 ファイル 1 判断。**なぜそうしたか**と、その帰結を残す。何をしたかはコードが語る。

このディレクトリは公開サイトに含まれない（`docs/build.mjs` は `docs/site/` だけを読む）。

## 他の置き場との違い

| 置き場 | 何を持つか |
|:--|:--|
| `docs/design/` | 方向性メモ。複数の判断をまたぐ物語 |
| **`{ADR_DIR}`** | **ADR。1 ファイル 1 判断** |
| `docs/tasks/` | 残タスク。PR 1 本ぶんの作業手順 |

方向性メモの中の判断が争点になった、または覆すのが高くつくと分かったら、
ADR に昇格させる。メモからは ADR にリンクし、判断の本体は片方にだけ置く。

## 規約

- ファイル名: `YYYY-MM-DD-english-slug.md`（**ファイル名は英語、本文は日本語**）
- status: `proposed` / `accepted` / `rejected` / `deprecated` / `superseded by [題](...)`
- 過去は書き換えない。学びは `## 補足` に日付付きで追記する
- 置き換えるときは新しい ADR を作り、**双方向にリンク**する

## 流れ

1. `proposed` で作る
2. 議論して直す
3. 決まったら `accepted`（または `rejected`）
4. 受理したら実装計画をタスクにし、PR とコードから ADR を参照する
5. 検証項目を走らせ、結果を `## 補足` に残す

作成・status 変更は `.agents/skills/adr-skill/scripts/` のスクリプトを使う。
