# 8a. 個人組織

## 目的

ToC のユーザーを、ToB とまったく同じ経路に載せる。

## なぜ

`organization.KindPersonal` は「1 人 1 組織」である。個人ユーザーを
hub のどこにも特別扱いとして書かないための仕組みで、
分岐を作らないことが目的そのもの。

## やること

- 初回ログイン時に個人組織を自動作成する。
  `user.Service.CreateIfNotExists`（`internal/domain/user/service.go`）が
  既に「初回アクセスでユーザー行を作る」場所なので、そこに寄せる。
- 個人組織にはその人だけのグループを 1 つ作り、既定のロールを与える。
- **`kind` で分岐するコードを書かない。**`AppliesEverywhere()` 以外に
  この列を読む場所を増やさない。増やしたくなったら設計を疑う。
- 既存ユーザーの移行方針を決める（`default` グループとの関係）。

## 完了条件

- 新規ユーザーが、管理者の操作なしに自分の組織を持つ。
- 個人ユーザーと企業ユーザーで、認可のコードパスが分かれていない。
