# 6b. Extended Card と A2A エンドポイント

## 目的

呼び出し元の RBAC で絞ったスキル一覧を返し、A2A の呼び出しを受ける。

## なぜ

**これが hub にしか書けない機能である。**権限グラフを持っていないと書けない。

A2A 仕様は、認証済みクライアントにだけ返す Extended Agent Card を定義している。
hub はそこに呼び出し元の権限で絞った一覧を返せる —— 同じ Agent が、
相手によって違う能力を名乗る。`ToolBox.Tools(ctx)` が
「そのユーザーが呼べるものだけ返す」のを A2A に持ち上げたものである。

## やること

- `GET /extendedAgentCard`（要 Bearer）。`Tools(ctx)` と同じく
  `auth.Service.Enforce` で絞る。**絞った一覧を返すだけでは足りない** ——
  実行時にも検査する。権限は 2 回の間に失効しうる。
- A2A のタスク受け口。認証は Keycloak、認可は 3b の代理チェーン。
- In-Task Authentication（二次資格情報）が要る場合は、A2A 仕様どおり
  クライアント側に取得させる。hub が代わりに持たない。
- 監査ログに `channel = 'agent'` とチェーンを残す。

## 完了条件

- 権限の違う 2 人が同じ Agent の Extended Card を取ると、スキル一覧が異なる。
- カードに載っていないスキルを直接呼んでも拒否される（一覧と実行の二重検査）。
- 委譲の無い呼び出しが、Agent 自身の権限を超えない。
