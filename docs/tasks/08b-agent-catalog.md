# 8b. Agent カタログ

## 目的

作った Agent を他の組織・他のユーザーから見つけて使えるようにする。

## なぜ / 注意

ここまでのタスクが全部入って初めて成り立つ。**先に作らないこと。**
公開とは「知らない相手が呼ぶ」ことであり、
委譲（3b）と Extended Card（6b）が無い状態でそれを許すと、
Agent の権限が誰のものか説明できなくなる。

## やること

- Agent の公開範囲（自組織のみ / 招待 / 公開）。
- 公開された Agent を他組織のユーザーが使うときの委譲の形を決める ——
  ここで初めて Keycloak Token Exchange（RFC 8693）が現実の要求になる可能性がある。
  方向性メモ §4.4 の判断を見直す唯一のタイミング。
- カタログ画面と、A2A の Agent Card による発見。
- 課金・レート制限。`ANTHROPIC_SESSION_TOKEN_BUDGET` と同じ問題を
  Agent 単位で解くことになる。

## 完了条件

- 他組織の Agent を発見して呼べ、その呼び出しが誰の代理なのか監査ログで説明できる。
- 公開した側が、いつでも公開を取り消せる。
