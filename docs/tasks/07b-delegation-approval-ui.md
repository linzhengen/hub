# 7b. 委譲の承認画面

## 目的

ユーザーが自分の代理権を、会話の外で、明示的に渡せるようにする。

## なぜ

委譲は「Agent に何ができるか」を決める操作である。既存のアクセス申請と同じく、
**起票と承認を別の人・別の画面に分ける**という非対称性をここでも保つ。
`AccessRequests.tsx` が形の雛形になる。

## やること

- `ui/web/src/pages/Delegations.tsx`。自分が渡した委譲の一覧、期限、失効。
- 自分に何が委譲されているかではなく、**自分が何を渡したか**を主にする。
  委譲元にとっての関心はそちら。
- 期限を必ず選ばせる。無期限はチェックボックスを外す操作にして、
  既定にしない —— 無期限の委譲は大きな判断で、そう読めるべきである。
- 失効を 1 クリックで。`useDangerConfirm` を使う（`window.confirm` は使わない）。
- 起票が AI 経由なら、承認画面にそう表示する
  （`access_requests.origin` が同じ問題を既に解いている）。

## 完了条件

- ユーザーが自分の代理権を渡し、一覧し、失効できる。
- 失効が即座に効く（3a の結合テストと同じ性質を UI から確認）。
